# タイピング練習 仕様書（改修版）

対象: `src/features/typing-japanese/` / `src/pages/tools/typing-japanese.astro`
改修前の記録は `spec-current.md`。差分は §7 にまとめてある。

---

## 1. 概要

ブラウザだけで動くタイピング練習ゲーム。ひらがなをローマ字で打つ「日本語モード」と、
プログラムの短いコードを打つ「プログラミングモード」の2つを持つ。
公開URL: `/tools/typing-japanese`

すべてクライアントサイドで完結し、入力内容をサーバーへ送らない。
スコアの永続化は行わない（ページを離れると消える）。

## 2. 本改修の目的

**スペースキーを押す必要がある箇所を、画面上で必ず見えるようにする。**

プログラミングモードの問題 110 問のうち 82 問が半角スペースを含むのに、
改修前は画面上でスペースがまったく見えなかった。`x = 5` は `x=5` と区別がつかず、
生徒が「なぜ進まないのか」を自力で気づけない。ここを直すのが本改修の主題である。

## 3. スペースマークの仕様

### 3.1 見た目

半角スペース1つを、次の見た目の**チップ**として描画する。

- 文字: `␣`（U+2423 OPEN BOX）
- 枠: 1px の実線、角丸
- 背景: ごく薄い塗り
- 幅: 等幅フォントの1文字ぶんを基準に、枠のぶんだけ左右に余白を足す

```
お題:   x  ␣  =  ␣  5
           ┌─┐   ┌─┐
           │␣│   │␣│   ← 薄い枠＋背景のチップ
           └─┘   └─┘
```

### 3.2 なぜこの形か

- **色だけに情報を乗せない**（DADS）。`␣` という字形と枠線という2つの手がかりがあるので、
  色覚特性や、教室のプロジェクタのように色が沈む環境でも判別できる。
- 等幅フォントで描くので、桁がずれてお題が読みにくくなることがない。
- `␣` は「空白」を表すために定義された Unicode 文字であり、意味が読み取りやすい。

### 3.3 コントラスト要件（DADS）

| 対象 | 必要な比 | ライト実測 | ダーク実測 |
|---|---|---:|---:|
| お題チップの `␣` vs チップ背景 | 4.5:1 以上 | 9.45:1 | 11.86:1 |
| お題チップの枠 vs カード背景 | 3:1 以上 | 4.76:1 | 3.76:1 |
| 入力チップの `␣` vs チップ背景 | 4.5:1 以上 | 6.53:1 | 10.44:1 |
| 入力チップの枠 vs 入力欄背景 | 3:1 以上 | 3.84:1 | 7.46:1 |

実測値は実装後に実ブラウザ上で DOM の実効色を取得して WCAG 式で算出したもの。
ライトモード・ダークモードの両方で満たすこと。

### 3.4 スクリーンリーダー

チップは `␣` を `aria-hidden="true"` で隠し、代わりに読み上げ用テキスト「スペース」を
`sr-only` で置く。結果として「エックス スペース イコール スペース ご」と読まれる。

### 3.5 適用範囲

| 場所 | 適用 |
|---|---|
| プレイ画面のお題（`question`） | する |
| プレイ画面の入力欄（`userInput`） | する（打ったスペースが見える） |
| 日本語モード | 同じ処理を通す。ただし日本語の問題にスペースは1件も無いので、実際には出ない |
| 結果画面・ホーム画面 | しない |

お題と入力欄で**同じ見た目**を使う。生徒が上下を見比べて「同じ形が並んだ＝合っている」
と判断できることを優先する。ただし入力欄側は「自分が打ち終えた文字」なので、
お題側と塗りの濃さを変えてよい（形は変えない）。

### 3.6 記号の強調との関係

改修前からある「プログラミングモードで記号を太字＋アンバー色にする」処理は残す。
スペースはその強調の対象外とし、スペースチップだけを当てる（二重に飾らない）。
記号の強調は**プログラミングモードのみ**、スペースチップは**両モード**で有効にする。

## 4. 画面構成

`GameState` は `'home' | 'playing' | 'result'` の3状態。1つの React コンポーネント
`TypingGame.tsx` が状態に応じて出し分ける。ページ遷移はしない。

### 4.1 ホーム画面（`home`）

| 区画 | 内容 |
|---|---|
| モード | タブ2つ: 「日本語」/「プログラミング」 |
| 難易度 | ラジオ3つ。日本語=やさしい/ふつう/むずかしい、プログラミング=入門/基礎/実践 |
| 言語 | プログラミングモードのときだけ表示。すべて/Python/JavaScript/HTML/CSS |
| 時間 | スライダー（30〜120秒、30秒刻み）＋ 30秒/60秒/120秒のボタン |
| スタート | ボタン1つ |

モードを切り替えると難易度と言語が初期値へ戻る（日本語→`normal`、
プログラミング→`beginner` + `all`）。

### 4.2 プレイ画面（`playing`）

- 左上に状態ラベル、右上に残り秒数（等幅・大きめ）。
  状態ラベルは日本語で「入力中」とする（`PLAYING` という英大文字は使わない）。
- 日本語入力（IME）を検出したら、お題の上に警告を出す（§4.2.1）。
- 中央のカードにお題を 4xl・等幅で表示。スペースは §3 のチップで描く。
- その下の枠に、これまでに打った文字と点滅カーソル。スペースは同じチップで描く。

### 4.2.1 IME 警告

IME がオンだと `keydown` の `key` が `'Process'` などになり、
これまでは誤入力にすらならず**画面が一切動かなかった**。原因が分からないまま
制限時間が過ぎるという壊れ方をするため、検出して知らせる。

検出条件（いずれか）: `event.isComposing` / `event.key === 'Process'` /
`event.keyCode === 229` / `compositionstart` イベント

表示: `role="alert"` の枠付き警告。
「日本語入力（IME）がオンになっています。半角英数に切り替えてください。」
＋ 切り替え方（Windows は半角/全角キー、Mac は英数キー）。

通常の1文字キーが入ってきた時点で消す。プレイ画面を離れたときも消す。

### 4.2.2 練習中の操作

| 操作 | 内容 |
|---|---|
| Backspace | 打った文字を1つ消す |
| Esc / 「やめる」ボタン | 中断して設定画面へ戻る |
| 「この問題をとばす」ボタン | 次の問題へ。飛ばした問題は完了数にも文字数にも入れない |

クリアできない問題や苦手な問題で制限時間いっぱい拘束されないようにするため。
改修前は中断もスキップも打ち直しもできず、リロードするしかなかった。

### 4.2.3 誤入力の知らせ方

改修前は誤入力しても画面が一切変化せず、「キーが効かない」「壊れている」と
受け取られる状態だった。誤入力のたびに 0.7 秒だけ次を出す。

- 入力欄の枠を赤の2pxにする
- 「✗ その文字はここには入りません。お題を見て打ち直してください。」を表示する

色だけに情報を乗せないため、枠の色と文言の両方を出す。
表示領域の高さは常に確保し、出入りで画面が動かないようにする。

### 4.3 結果画面（`result`）

完了問題数 / 正解文字数 / 誤入力数 / 正解率(%) / 分速（1分あたりの文字数） /
かかった時間 の6枚のカードと「ホームに戻る」ボタン。

分速 = 正解文字数 ÷ 経過秒数 × 60。制限時間を選ばせている以上、速さの指標を出す。
スコアを保存しないことを画面にも明記する。

## 5. 問題データ

`src/features/typing-japanese/problems/*.json` を `import.meta.glob` で eager 読み込み。

```ts
interface Problem {
  question: string;          // 画面に出すお題
  answers: string[];         // 正解として受け付ける入力（複数表記可）
  language?: ProgrammingLanguage;  // プログラミングモードのみ
}
```

| ファイル | 問題数 | 内訳 |
|---|---:|---|
| `easy.json` | 52 | — |
| `normal.json` | 50 | — |
| `hard.json` | 49 | — |
| `programming-beginner.json` | 40 | すべて `common` |
| `programming-intermediate.json` | 50 | 各言語10 + `common` 10 |
| `programming-advanced.json` | 50 | 各言語10 + `common` 10 |

プログラミングモードで言語を選ぶと `common` も一緒に出題される。
基礎・実践に `common` が1問も無く、言語を選ぶと10問しか出ずに周回していたため、
各20問になるよう追加した。入門は全問が言語共通なので言語を選ばせない（§4.1）。

## 6. ゲーム進行のロジック（`useTypingGame.ts`）

### 6.1 開始

1. モードと難易度から JSON を1つ選ぶ
2. プログラミングモードなら言語で絞る（`all` は全件、それ以外は
   `language === 選択言語 || language === 'common'`）
3. Fisher–Yates でシャッフルして先頭 50 問（`MAX_PROBLEMS`）
4. 0問なら即 `result`、1問以上なら `playing`

### 6.2 入力判定

`document` の `keydown` を購読する。

- Ctrl / Meta / Alt との同時押しは無視
- スペースキーは `preventDefault()` してからスペースとして扱う（ページのスクロール防止）
- `event.key.length !== 1` のキーは無視

1文字ごとに、

1. 日本語モードは小文字化、プログラミングモードはそのまま、入力末尾に足す
2. `answers` のうち新しい入力で**前方一致**するものに絞る
3. 候補があれば入力を確定する。さらに、
   - 完全一致があり、**かつより長い候補が残っていない**ならクリア
   - 完全一致があっても長い候補が残っているうちは**確定を保留する**（§6.3）
4. 候補が0本になったら、
   - 直前までの入力がすでに完全一致していたなら、そこでクリアとし、
     今回のキーは**次の問題の1文字目として引き継ぐ**（§6.3）
   - そうでなければ誤入力。`wrongChars` を +1 し、入力は伸ばさない（打ち直せる）

### 6.2.1 「ん」の表記ゆれ

日本語モードに限り、出題時に各 `answers` を展開して
**「ん」を `n` でも `nn` でも打てるようにする**（`romaji.ts`）。

- `nn` は常に受け付ける
- 単独の `n` は、その「ん」の直後が母音・`y`・`n` でないときだけ受け付ける
  （`kanniiku` は「かんいいく」になってしまうため、こういう箇所は `nn` に限る）

プログラミングモードには通さない。`print` が `prinnt` になってしまうため。

問題データを1問ずつ直す方式は、問題を足すたびに漏れるのでとらない。

### 6.3 短い表記が長い表記の前方一致になっている場合

`arigato` / `arigatou` のように、ある答えが別の答えの前方一致になっている問題が
日本語モードに10ペアある。「ん」の展開でも `hon` / `honn` の形で必ず生じる。

完全一致した瞬間に確定すると、`arigatou` と**正しく打った生徒**の最後の `u` が
次の問題への誤入力になっていた。これを次のように改める。

- 完全一致しても、より長い候補が残っているうちは確定しない（IME が「ん」を
  保留するのと同じ考え方）
- 次のキーで長い候補に伸びればそのまま続行
- 次のキーでどの候補にも伸びなくなったら、その時点で**直前の完全一致でクリア**とし、
  そのキーを次の問題の1文字目として引き継ぐ
- 引き継いだキーが次の問題の頭として成立しない場合は**捨てる。誤入力には数えない**
  （余りが出たのは複数表記を許しているこちらの都合なので、正解率に響かせない）

### 6.3 スコア

```
correctChars   += クリアした入力文字列の長さ
completedProblems += 1
accuracy = correctChars / (correctChars + wrongChars) * 100
```

### 6.4 終了条件

- 最後の問題をクリアしたとき
- 残り時間が 0 になったとき。このとき**打ちかけの文字も `correctChars` に加える**。
  完答時にだけ加算する作りだと、時間切れの瞬間に打っていた文字がまるごと消えて
  正解率が実力より低く出ていた（13文字中12文字正解で 0% になっていた）。

### 6.5 タイマー

開始時に「締め切り時刻」を持ち、そこから残りを計算する（0.2秒ごとに更新）。
1秒ごとに `setInterval` を張り直す作りだと、タブが非アクティブなときのスロットリングで
実時間とずれる。また打鍵のたびに effect が再実行される依存の書き方をすると
カウントダウンが止まってしまうため、時間切れ処理から入力を読むのは ref 経由にする。

## 6.6 アクセシビリティ上の決めごと

| 対象 | 対応 |
|---|---|
| 難易度・言語のラジオ | `aria-label` を直接渡す。`<label htmlFor>` は Radix の `role="radio"` に効かない |
| ラジオの丸 | 枠を `slate-500`。shadcn 既定の `border-input` は白背景に 1.26:1 で、選択肢の位置が見えない |
| ラジオのまとまり | `aria-labelledby` で見出しと結ぶ |
| スライダー | `thumbLabel` でつまみに名前を付ける。`role="slider"` を持つのは Thumb |
| お題 | `role="status" aria-live="polite"`。切り替わりを読み上げる |
| 誤入力の知らせ | 同上。文言で伝える |
| スタート直後 | プレイ領域にフォーカスを移す。改修前は `BODY` に脱落していた |
| ボタン・ラベル | 16px 以上 |

## 8. 実装メモ

- スペースチップは `TypingGame.tsx` 内の描画関数として持つ。お題と入力欄で
  同じ関数を使い回し、見た目の差は引数で切り替える。
- Tailwind のクラス名を文字列連結で組み立てないこと（静的走査から漏れて CSS が消える。
  プロジェクトの `AGENTS.md` 参照）。
- 判定ロジック（`useTypingGame.ts`）は本改修では変えない。マークは表示だけの話であり、
  入力として受け付ける文字は半角スペースのまま。`␣` を打っても正解にはならない。
