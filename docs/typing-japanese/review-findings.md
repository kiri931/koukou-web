# タイピング練習 動作検証の記録（2026-08-04）

3つの検証を独立に走らせた結果。**本改修（スペースマーク）では直していない**問題が
多数あるため、次に何を直すかの判断材料としてここに残す。

検証の内訳:
- ロジック検証 — 全261問・answer 515件の入力シミュレーション、vitest でのフック実測
- 問題データ検証 — ローマ字変換表との突き合わせ、全件の機械検査
- UI/アクセシビリティ検証 — 実ブラウザでの操作とコントラスト実測

「実測」と書いてあるものは実際に動かして得た値。それ以外は読み取りによる指摘。

---

## A. クリア不可能な問題（最優先）

ロジック検証と問題データ検証の両方が独立に指摘し、実データでも確認済み。

| ファイル | question | 内容 |
|---|---|---|
| `hard.json` | `"しごと,べんきょう"のまいにち` | answers 8件中4件に `ï`(U+00EF) が混入。日本語キーボードで打てない。残り4件は `benkyo` なので「べんきょう」を正しく打つと**詰む**（実測: 打ち直しても復帰不能） |
| `hard.json` | `きょうは*まいにち*のひとつ` | answers 4件すべて `...nohito` で終わり、**末尾の「つ」が欠落** |
| `hard.json` | `ばんごはんに,さかなをたべた` | answers 2件とも**カンマ `,` が無い**。お題と一致しない |
| `normal.json` | `まちでともだちにあう` | answers 2件とも `...niaou`（「にあおう」）。正しい `niau` が未登録 |
| `normal.json` | `ちいさなこえでいう` | answers 2件とも `...koedeyuu`（「こえでゆう」）。正しい `iu` が未登録 |
| `normal.json` | `かぞくとしょくじ` | answers 4件すべて `...shokujii`。正しい `shokuji` が未登録 |
| `normal.json` | `きんようびのひる` | 唯一の answer が `kinyoubinohiru`。これは「きにょう」。`kinnyou...` が正しい |

やり直し手段（Backspace・スキップ・中断）が無いため、これらを引いた生徒は
**時間切れまで待つしかない**（実測: プレイ中に操作可能な要素が0件）。

## B. 「ん」の表記が揃っていない

- 「ん」を含む問題は **58問**。うち **53問は `nn` 表記が1件も無い**。
- 「ん」を常に `nn` と打つスタイルでは、**151問中62問で誤入力が出る**（実測）。
- 逆に `nn` でしか通らない問題も混在しており、**ファイル内でルールが割れている**。
- 詰みはせず誤入力1回で復帰できるが、正解率の計測としては不正確。

## C. 短い答えが先に確定して、正しく打つと損をする

`useTypingGame.ts` は完全一致した瞬間に次の問題へ進むため、
ある answer が別の answer の前方一致になっていると長い方に到達できない。**10ペア/6問**。

実測: 「ありがとう」を `arigatou` と正しく打つと `arigato` の時点でクリアし、
**余った `u` が次の問題の誤入力になる**（correct+7 / wrong+1）。
`きょう` (`kyo` ⊂ `kyou`)、`おはよう`、`ぎゅうにゅう`、`まいにちべんきょう` も同様。

**かな通りに正しく打つ生徒ほど正答率が下がる。**

## D. 時間切れ時に打ちかけの文字がスコアに入らない

`correctChars` は完答時にまとめて加算する作りのため、時間切れの瞬間に
打ちかけだった文字は0扱いになる。誤入力だけは即時カウントされる。

実測（本改修後のブラウザでも再現）: `(1, 2` まで5文字正しく打った状態で時間切れ →
その5文字は正解文字数に入らなかった。

## E. IME オン時に完全な無反応になる（未実測）

`event.isComposing` を見ておらず、`event.key.length !== 1` で弾いている。
日本語入力がオンだと `event.key === 'Process'`（7文字）になるため全部無視され、
**誤入力にすらならず画面が一切動かない**はず。

ローマ字入力の練習ツールで生徒が IME をオンにしている確率は高く、
かつ誤入力時の視覚フィードバックが無いので原因が分からない。

**ブラウザでの実測はできていない**（jsdom でも実ブラウザでも IME を再現する手段が無かった）。
本改修では応急処置として、ページの説明とFAQに「IMEをオフにしてください」を明記した。
コード側の対処（`isComposing` を見て画面に警告を出す）は**未実施**。

## F. 誤入力のフィードバックが画面に無い

実測: `zzz` と3回誤打しても画面は一切変化しなかった。結果画面の「誤入力数」で初めて分かる。
教室では「キーが効かない」「壊れている」と受け取られる。

## G. プログラミングモードの出題数の偏り

`filterProgrammingProblemsByLanguage` は `common` を必ず含めるが、
intermediate / advanced には `common` が1件も無い。

| 難易度 | 言語を選んだときの出題数 |
|---|---|
| 入門 | 40問（全問 `common` なので言語ラジオが何も絞らない） |
| 基礎 | 各言語10問 |
| 実践 | Python/JS 各10問、**HTML 5問・CSS 5問** |

`MAX_PROBLEMS = 50` に対して少なすぎ、60秒でも周回する。
また `<a href="#">Link</a>` が intermediate と advanced に重複して存在する。

## I. 支援技術（未対応）

- **難易度・言語のラジオにアクセシブルネームが無い**（実測）。`<label htmlFor>` が
  Radix の `<button role="radio">` に効いておらず、読み上げで区別できない。
- スライダーにも名前が無い。radiogroup / tablist にグループ名が無い。
- `aria-live` / `role="status"` がページ内に0件。お題の切り替わりも結果画面の出現も通知されない。
- スタート後にフォーカスが `BODY` に脱落する（実測）。

## J. 本改修で対応済み

- スペースキーの位置が見えない → `␣` チップで可視化（§ `spec.md` §3）
- 折り返し位置のスペースが消える → チップを要素にしたことで解消。
  幅247px（375px相当）でお題を折り返させても、印3つがすべて幅28pxを保ち消えないことを実測。
- `PLAYING` 英大文字バッジ → 「入力中」16px
- 見出し・ラベルの不要な `uppercase`、140行目の逆転していた三項演算子 → 削除
- 記号ハイライトの amber-500 (2.13:1) → amber-700 / dark:amber-400
- 解説文の 14px → 16px、`max-w-5xl` → `max-w-3xl`
- 解説にプログラミングモードとスペース表示の説明を追加
- FAQ のスコア保存の記述を実装に合わせて訂正、IME の項目を追加

## K. 2回目の改修で対応したもの

指示を受けて A・B・C・E に対応した。

### A（クリア不可能な問題）— 対応済み
7問すべての答えを訂正した。`ï` の除去、「つ」とカンマの補完、
かなと矛盾していたローマ字（`niaou` → `niau` 等）の修正。

### B（「ん」の表記）— 対応済み
2段階で対応した。

1. **データ側**: 「ん」の直後に な行/や行 が来る5問で、n が1つ足りず別の読みに
   なっていたものを訂正（`bangohanni,` → `bangohannni,`、`konnichiha` →
   `konnnichiha`、`kanniiku` → `kannniiku`、`kabannonakani` → `kabannnonakani`、
   `takusanyomu` → `takusannyomu`）。あわせて「ん」の直後の を を `o` と綴って
   別の読みになっていた答え9件を削除（同じ問題に正しい `wo` 版が別途あるため詰まない）。
2. **ロジック側**: `romaji.ts` を追加し、日本語モードの答えを出題時に展開して
   「ん」を `n` でも `nn` でも打てるようにした。データを1問ずつ直す方式は
   問題を足すたびに漏れるため採らなかった。

検証（全問シミュレーション）:

| 打ち方 | easy | normal | hard |
|---|---|---|---|
| 登録どおり | 52問完了 誤入力0 | 50問完了 誤入力0 | 49問完了 誤入力0 |
| 「ん」を常に `nn` | 52問完了 誤入力0 | 50問完了 誤入力0 | 49問完了 誤入力0 |
| 「ん」を常に単独 `n` | 52問完了 誤入力0 | 4問が打ち切れない | 4問が打ち切れない |

単独 `n` で打ち切れない4問は、いずれも「ん」の直後が な行/や行 のもの。
実際の IME でも単独 `n` では打てないため、これは正しい挙動。

実ブラウザでも「あたらしいぱそこん」を `atarashiipasokonn` でクリアできることを確認した。

### C（前方一致で長い表記に到達できない）— 対応済み
確定を保留する方式に変更（`spec.md` §6.3）。B の対応で `hon` / `honn` の形が
大量に発生するため、C を直さないと B が逆効果になる。
余ったキーは誤入力に数えない。

### E（IME オン時の無反応）— 対応済み
`isComposing` / `key === 'Process'` / `keyCode === 229` / `compositionstart` で検出し、
`role="alert"` の警告を出すようにした。

ただし**実際の IME での動作確認はできていない**（IME を再現する手段が無い）。
確認できたのは、`compositionstart` を送ったときに警告が出ること、
通常のキーで消えること、その状態で入力が正常に続くことまで。
教室で実機確認してもらう必要がある。

## L. 3回目の改修で対応したもの

残り全部という指示を受けて D・F・G・H・I とやり直し手段・速度指標に対応した。

### D（時間切れ時のスコア欠落）— 対応済み
時間切れの時点で打ちかけだった文字を `correctChars` に加えるようにした。
実ブラウザで確認: 12文字打った状態で時間切れ → 完了0問・正解文字数12・正解率85.7%。
改修前は同じ状況で正解文字数0だった。

あわせてタイマーを締め切り時刻ベースに直した。1秒ごとに `setInterval` を
張り直す作りだとタブが非アクティブなときにずれるため。
（打ちかけの文字を読むのに effect の依存を増やすと、打鍵のたびにタイマーが
張り直されてカウントダウンが止まる。そこは ref 経由にした。）

### F（誤入力のフィードバック）— 対応済み
入力欄の枠を赤2pxにし、「✗ その文字はここには入りません。お題を見て打ち直してください。」
を 0.7 秒表示する。色だけに頼らないよう文言も出す。実ブラウザで表示と消灯を確認。

### G（出題数の偏り）— 対応済み

| | 改修前 | 改修後 |
|---|---|---|
| 基礎 × 各言語 | 10問 | 20問 |
| 実践 × Python / JS | 10問 | 20問 |
| 実践 × HTML / CSS | **5問** | 20問 |

基礎・実践に `common` を各10問追加、実践の HTML/CSS を各10問に増やした。
基礎と完全に重複していた `<a href="#">Link</a>` を実践から外し、
実践にあった `try:`（4文字）は実践相当の書き方に差し替えた。
入門は全問 `common` で言語を選んでも出題が変わらなかったため、
言語ラジオを出さずに理由を書くようにした。

### H（コントラスト）— 対応済み

| 対象 | 改修前 | 改修後 |
|---|---:|---:|
| スタート/ホームに戻る 白文字 | 4.02:1 | 5.86:1（16px） |
| ラジオの丸の枠 | **1.26:1** | 4.76:1（ダーク 7.13:1） |
| 入力欄の枠 | 1.42:1 | 3.5:1 相当 |

ラジオの丸は shadcn 既定の `border-input` のままで 1.26:1 だった。
支援技術以前に「どこが選択肢なのか」が見えていなかった。

カードの外枠は `slate-300` のまま残した。AGENTS.md が定めている枠線の色であり、
操作対象の境界ではなく飾りの区切りだと判断したため。ページ背景に対しては 1.42:1。

### I（支援技術）— 対応済み
- ラジオに `aria-label`（`<label htmlFor>` は Radix の `role="radio"` に効かない）
- ラジオのまとまりに `aria-labelledby`
- スライダーのつまみに名前（`slider.tsx` に `thumbLabel` を追加。他ツールに影響しない追加のみ）
- お題と誤入力の知らせに `role="status" aria-live="polite"`
- スタート直後にプレイ領域へフォーカスを移す（改修前は `BODY` に脱落）

実ブラウザで、ラジオ8個すべてに名前が付き、スライダーに「制限時間（秒）」が付き、
ライブ領域が2つあり、スタート後のフォーカスがプレイ領域に来ることを確認した。

### やり直し手段 — 対応済み
Backspace で1文字削除、「この問題をとばす」、「やめる（Esc）」。
実ブラウザで3つとも動作確認。飛ばした問題は完了数にも文字数にも入れない。

### 速度指標 — 対応済み
結果画面に「分速（1分あたりの文字数）」と「かかった時間」を追加。
