## 1. 何をする道具か

`ax+b=c` のような等式を、指定された文字について解く練習をする。
情報Iのプログラミングで変数の式を組み替えるときの土台にあたる。

生徒はブラウザで解いて自己採点する。先生はA4のプリントとして印刷して配れる。
**サーバーには何も送らないし、端末にも何も残さない**（9-3 参照）。

## 3. 出題

### 3-1. 問題バンク

`data/questions.ts` に **20問**。1問は次の5つを持つ。

| 項目 | 中身 |
|---|---|
| `id` | 1〜20 の通し番号 |
| `prompt` | 問題文。数式は `\( \)` で囲んだ LaTeX |
| `choices` | 選択肢の LaTeX 文字列。**3つ**（正解1・誤答2） |
| `answer` | 正解の LaTeX 文字列。`choices` のどれかと完全に一致する |
| `explain` | 解説。数式は `\( \)` で囲む |

扱う型は、移項するだけのもの（`3x-5y+7=0`）、かっこを展開するもの（`A=3(2x+y)`）、
分数係数のもの（`V=\frac{1}{3}Sh`）、逆数を含むもの（`\frac{a}{x}=b`）、
通分が要るもの（`\frac{1}{x}+\frac{1}{y}=\frac{1}{a}`）まで。
文字式のまま答えるものが中心で、数値だけの答えになる問題は無い。

誤答2つは、多くの問題で **正解の符号を変えたもの・分子と分母を入れ替えたもの** になっている。

### 3-2. 抽出

- バンク20問を毎回シャッフルし、先頭から出題数だけ取る。**同じ問題は重複しない**（実測）。
- さらに **問題ごとに選択肢の並び順もシャッフルする**。正解の位置は固定されない。
- 抽出は次の3つのときに走る。
  - ページを開いたとき
  - 「出題を更新」を押したとき
  - 「別の問題に変える」を押したとき
- 「やり直し」では抽出し直さない（同じ問題が残る。実測で確認）。

### 3-3. 出題数

入力欄は `type="number"`、既定値は 10。押されたときの値を次の順で丸める。

1. 数値にならない値は 10 とみなす
2. 小数は切り捨て
3. 1 未満は 1、20 超（＝バンクの件数超）は 20 に丸める

実測した結果は次のとおり。

| 欄に入れた値 | 出題数 | 備考 |
|---|---|---|
| `0` | 1 | |
| `-5` | 1 | |
| `3.7` | 3 | **欄の表示は `3.7` のまま**で、実際の問題数とずれる |
| `999` | 20 | バンク全問 |
| 空欄 | 1 | **10 に戻るのではなく 1 問になる** |
| `abc` | 1 | `type="number"` が弾いて欄が空になり、空欄と同じ扱い |

上の2件（`3.7` と空欄）は、いまの実装が意図してそうしているというより、
`Number("")` が `0` になることの結果である。9-2 に課題として書いた。

## 4. 解答方式

タブで「択一式」「記述式」を切り替える。**切り替えると、それまでの解答と採点結果は
すべて消える**（得点・正解バッジ・解説の自動展開もリセットされる）。

### 4-1. 択一式（既定）

- 選択肢3つをラジオボタンで縦に並べる。行全体が `<label>` なので、文字のどこを
  押しても選べる。
- 選べるのは1問につき1つ。採点後は `disabled` になり選び直せない。

### 4-2. 記述式

- MathLive の `<math-field>` を1問に1つ置く。プレースホルダは `例: x=(5y-7)/3`。
- `math-virtual-keyboard-policy="onfocus"` なので、欄をタップ／クリックすると
  数式キーボードが出る。分数・変数はそこから入れる。
- 入力は LaTeX 文字列として保持される。
- ルールの枠に、記述式のときだけ次の4行が出る。
  数式キーボードの出し方／分数と変数の入れ方／**求める文字から `x=` のように書くこと**／
  **値が同じなら、項の順序・展開・通分・小数の違いは正解になること**。

## 5. 採点

「採点する」を押した時点の解答を、その場ですべて突き合わせる。
無解答は不正解として数える。**未解答があっても警告は出ない**し、確認もされない。

### 5-1. 択一式の判定

選んだ選択肢の文字列が `answer` と **完全に一致**すれば正解。
選択肢は `answer` から作られているので、ここで取りこぼしは起きない。

### 5-2. 記述式の判定

**式を実際に評価して、値が同じかどうかで判定する。**（`lib/equivalence.ts`）
文字列の見た目は問わない。手順は次のとおり。

1. 生徒の入力と `answer` の両方を LaTeX から素の式に均す
   （`\dfrac`→`\frac`、`\frac{A}{B}`→`((A)/(B))`、`^{2}`→`^(2)`、`\cdot` `\times`→`*`、
   `\left` `\right` と空白は削除）
2. `=` で2つに割り、再帰下降で式として読む。`4xy` や `2(x+1)` のように記号なしで
   並んだものは掛け算として読む
3. **左辺が正解と同じ変数1文字であることを求める**（5-2-1）
4. 両辺に出てくる変数へ、同じ値を入れて右辺どうしを比べる（5-2-2）

どちらかが式として読めなかったときだけ、従来の文字列一致（`normalizeAnswer`）に任せる。
**読めない入力で判定が甘くなることはない**（従来と同じ厳しさに戻るだけ）。

#### 5-2-1. 左辺の決まり

- 「`x` について解け」なので、**`x=` から書くことを求める**。右辺だけ書いても正解にしない。
- 違う文字について解いていたら、不正解にしたうえで
  「`y` について解いた形（`y=` …）で答えてください。」と画面に出す。
- **大文字と小文字は別の変数**として扱う（`X` と `x` は別物）。
- 右辺に求める文字自身が残っている式（`x=2x-6y-1`）は「解けていない」ので不正解にする。

#### 5-2-2. 値の比べ方

- 変数には **0 から離れた値**（絶対値 1.25〜8.75）を入れる。正負を混ぜて符号の違いを拾う。
- **8組そろうまで代入を試す**（上限64回）。分母が0になるなど評価できない組は捨てて引き直す。
- 8組すべてで一致すれば正解。1組でも外れたらその場で不正解。
- 一致とみなす**相対誤差は 1e-9**。
- 評価できる組が3つ未満だった式は、判定材料が足りないとみなして文字列一致に任せる。
- **乱数は固定の種から作る。** 同じ解答を何度採点しても結果は必ず同じになる。

### 5-3. 記述式で通る書き方・弾かれる書き方（実測）

`lib/equivalence.test.ts` で常時検査している。**42件すべて通っている**（2026-08-05）。

正解にする書き方（`x=\dfrac{5y-7}{3}` が正解の問題ほか）:

| 生徒の入力 | 正解データ |
|---|---|
| `x=\frac{5y-7}{3}` / `x=(5y-7)/3` | `x=\dfrac{5y-7}{3}` |
| `x=\dfrac{-7+5y}{3}`（項の順序） | 同上 |
| `x=\dfrac{5}{3}y-\dfrac{7}{3}`（分配した形） | 同上 |
| `x=\dfrac{7-5y}{-3}`（分母を負に） | 同上 |
| `x=\dfrac{10y-14}{6}`（**約分していない形**） | 同上 |
| `a=3b+2` / `a=2+b\cdot3` / `a=2+3\times b` | `a=2+3b` |
| `x=pr-pq` / `x=(r-q)p`（展開・因子の順序） | `x=p(r-q)` |
| `x=n+\dfrac{k}{m}` / `x=\dfrac{k+mn}{m}`（通分） | `x=\dfrac{k}{m}+n` |
| `x=t+0.5y`（**小数**） | `x=t+\dfrac{y}{2}` |
| `x=\dfrac{-ay}{a-y}`（分子分母を同時に符号反転） | `x=\dfrac{ay}{y-a}` |
| `x=\dfrac{1}{4}\cdot\dfrac{P}{y}` | `x=\dfrac{P}{4y}` |

不正解にする書き方:

| 生徒の入力 | 理由 |
|---|---|
| `x=\dfrac{7-5y}{3}` / `x=\dfrac{5y+7}{3}` | 値が違う（符号の誤り） |
| `x=\dfrac{k+n}{m}` | 値が違う（割る順序の誤り） |
| `x=2x-6y-1` | 右辺に `x` が残っている＝解けていない |
| `\dfrac{5y-7}{3}` | `x=` を書いていない |
| `X=\dfrac{5y-7}{3}` | 大文字・小文字が違う |
| `y=…`（別の文字について解いた） | 求める文字が違う。理由を画面に出す |

**問題バンク20問の点検もテストに含めている。**

- 20問すべての `answer` が式として読め、左辺が変数1文字であること
- 正解そのものを入力すれば必ず正解になること
- **40個ある誤答の選択肢を入力したとき、1つも正解に漏れないこと**

### 5-3-1. この方式で許してしまうこと

値が同じであれば通すので、次は**正解として扱われる**。

- 約分していない形（`x=\dfrac{10y-14}{6}`）
- `0.5` と `\dfrac{1}{2}`

「もっと簡単にできます」と伝える仕組みは今のところ無い（11-1 参照）。

### 5-4. 得点とコメント

`得点 / 出題数` と正解率（四捨五入した整数％）を出し、得点に応じたコメントを1つ出す。

| 条件 | コメント |
|---|---|
| 全問正解 | 満点！移項と係数処理が完璧です。 |
| 80%以上 | とても良いです。符号と割り算の扱いを再確認すると満点が見えます。 |
| 50%以上 | 基礎はできています。移項時の符号ミスに注意！ |
| それ未満 | まずは移項→係数で割るの手順を丁寧に練習しましょう。 |

境目は `Math.ceil(出題数 × 0.8)` と `Math.ceil(出題数 × 0.5)` で決まる。
10問なら8問以上・5問以上。

## 8. 印刷

「印刷（A4）」で下からシートが出る。チェックは3つ。

| チェック | 既定 | 効果 |
|---|---|---|
| 氏名・学年欄を含める | オン | ページ下部に「等式の変形テスト ／ 氏名：… ／ 学年：… 組：… 番：…」を固定表示 |
| 解答を含める | オフ | 各問の下に「解答: 〜」を出す |
| 解説を含める | オフ | 各問の下に解説の枠を出す |

チェックの状態は `document.body` のクラス（`print-show-answers` など）として持ち、
印刷用CSSがそれを見て表示を切り替える。「印刷する」を押すと 150ms 後に
`window.print()` を呼ぶ。

印刷時の体裁は `@page { size: A4; margin: 12mm }`。ヘッダー・タブ・ボタン類・
採点結果・画面用の解説は消え、問題カードだけが残る。カードは `break-inside: avoid`
なのでページ途中で割れない。数式の色は黒に固定する。

**チェックの状態はシートを閉じても保持される**が、ページを再読み込みすると既定に戻る。

## 9. 保存しないもの・記録しないもの

- サーバーへの送信は一切ない。すべてブラウザの中だけで動く。
- **localStorage も IndexedDB も使っていない。** 得点・解いた問題・間違えた問題は
  どれも残らない。ページを閉じるか再読み込みすると、すべて消えて新しい10問になる。
- 「前回の続き」「間違えた問題だけもう一度」はできない。

## 11. 今後の課題

ここから先は**現状ではない**。決まったら別途仕様に起こす。

### 11-1. 「もっと簡単にできます」を伝える

5-3-1 のとおり、約分していない形（`x=\dfrac{10y-14}{6}`）も小数も正解になる。
判定としてはそれでよいが、**正解にしたうえで「約分できます」と添える**ことはできる。
やるなら、判定とは別の仕組みとして足す。

### 11-2. 出題数の欄の丸め方

- 空欄で「出題を更新」を押すと 1 問になる。既定の10問に戻るほうが素直。
- `3.7` と入れると3問出るのに欄の表示は `3.7` のまま。押した時点で丸めた値を
  欄にも書き戻したい。

### 11-3. 選択肢が3つしかない

当てずっぽうで 1/3 が当たる。誤答が「符号違い」に寄っているので、
符号だけを見る癖もつきやすい。4つに増やす場合、20問すべてに誤答を1つずつ足す作業になる。

### 11-4. 学習の記録が残らない

同じ道具立てとしては、覚える君（`src/features/anki/`）が FSRS と IndexedDB で
記録を持っている。等式の変形でも「間違えた問題を優先して出す」ことはできるが、
それをやるなら覚える君と同じ土台に乗せるのか、この道具だけで持つのかを先に決める。

### 11-5. 文字サイズを16pxにそろえる

10章の3か所。選択肢と数式入力欄は生徒がいちばん見る場所なので、優先度は高い。

### 11-6. 未反映のUI提案がある

`ui-compare` に「等式の変形テストで、問題を最初に出す」（`20260802-equation-questions-first`、
2026-08-02、status: open）が残っている。ルール・使い方・FAQを下に畳み、
開いた直後に1問目が見える構成にする、という内容。まだ取り込んでいない。
