# 計算技術検定ドリル 仕様

対象: `src/features/calc-drill/` と、それが使う `src/features/scientific-calculator/`
この文書は **どの問題を出し、どう打たせ、どう見せるか** を書く。
Astro のページ構成・デプロイ・SEO 文言は対象外。

---

## 1. なぜ書き換えるのか

いまのドリルは、**140問のうち最後まで打てて答えも合うのが 49問しかない**。

この数字は推測ではなく、全問題のキー列を実際の電卓ロジック（`useCalculator`）に
1キーずつ流し込んで測った結果（2026-08-05 時点）。内訳は次のとおり。

| 症状 | 問題数 | 原因 |
|---|---|---|
| 押すべきボタンが存在しない | 65 | 問題データのガイド用語（`x²` `√` `log` `sin` `π` `Shift` `°'"` …）が、キーパッドの action 名（`^2` `sqrt(` `log(` `pi` `toggle-shift`）に変換されていない |
| 最後まで打てるが `=` でエラー | 19 | `×10ⁿ` キーが `10^(` と **かっこを開いたまま閉じない**。`3.46*10^(-5` のまま `=` を押すので式が壊れている |
| 完走するが答えが違う | 7 | 問題データそのものの誤り |
| 正常 | 49 | |

**「ハイライトされた通りに打ったのに `=` でエラーになる」という報告は、
2段目の19問すべてで確実に再現する。** 生徒の打ち方が悪いのではなく電卓側のバグである。

書き換えの狙いは3つ。

1. **打てない問題をゼロにする** — ガイド用語とキーの対応を作り、足りないキーを足す。
2. **間違った答えを教えない** — 「ガイド通りに打った結果」と「記載の答え」が
   合っているかをテストで常時検算し、合わないものは出題しない。
3. **目線を動かさずに打てるようにする** — 問題文・入力中の式・次に押すキーを
   電卓の画面の中に集約し、その真下にキーパッドを置く。

---

## 2. 決まっていること（前提）

- 出題範囲は **3級・4級の両方**。関数計算・実務計算も落とさず、
  **足りないキーは電卓側に足して救う**。
- レイアウトは **ディスプレイ集約型**（§5）。
- 問題データの誤りは **ビルド時の自動検算** で止める（§6）。

## 3. 電卓側の仕様変更

`CalcKeypad` と `useCalculator` は **ドリルと単体の関数電卓ページ
（`/tools/scientific-calculator`）で共有している**。ここの変更は両方に効く。
どれも単体の電卓としても正しい方向の修正なので、共有のまま直す。

### 3-1. `=` を押したとき、閉じ忘れたかっこを自動で閉じる

`=` の評価直前に、開いたままのかっこの数だけ `)` を補ってから評価する。
実際の関数電卓と同じ挙動で、生徒が末尾の `)` を省いても答えが出る。

```
評価する式 = expression + ')'.repeat(max(0, かっこ残数))
```

`x²` `√(` `sin(` `xʸ` など、かっこを開く系のキーすべてがこれで救われる。

> **実測**: この1点だけを入れて全問題を流したところ、`=` でのエラーは
> **19問 → 0問**になり、既存のテスト23件はすべて通った。

### 3-2. `×10ⁿ` は「かっこを開く」のをやめ、指数表記 `e` を入れる

3-1 だけでは `×10ⁿ` は直らない。`10^(` は **後ろに続く式を全部飲み込む**ので、
末尾で閉じても意味が変わってしまうため。

```
いまの動き   (-7.15×10ⁿ4 + 3.82×10ⁿ4) ÷ …
             → "(-7.15*10^(4+3.82*10^(4)/…"   ← 4+3.82*10^4 が指数になる
```

`×10ⁿ` は指数部を**その直後の数値だけ**に限定しなければならない。
実際の電卓の EXP キーと同じで、これは指数表記のリテラルそのもの。

```
新しい動き   base + "e"      →  "3.46e"  →  "3.46e-"  →  "3.46e-5"
```

`3.46e-5` は mathjs がそのまま数値リテラルとして読む。
`-` は既存の `applyInsertOperator` が末尾 `e` を演算子と見なさないのでそのまま付く。

- 画面表示では `3.46e-5` を **`3.46×10⁻⁵`** と描く（`formatExpressionForDisplay` に追加）。
  生徒が「打った通りに見える」ことが大事なので、`e` のまま見せない。
- 自然対数の底 `e` キーとは字面が衝突するが、`e` 単独は定数、
  `数値 + e` は指数表記、という mathjs の字句解析どおりで矛盾しない。

> **実測**: 3-1 と 3-2 を入れた状態で全問題を流し、`=` エラーは 0問になった。

### 3-3. ガイド用語 → キー action の変換表を作る

`parseGuide.ts` の変換表は現在 `×` `÷` `EXP` の3つしかない。次の表に置き換える。

| ガイドの用語 | action | 備考 |
|---|---|---|
| `×` | `*` | |
| `÷` | `/` | |
| `EXP` | `exp10` | §3-2 |
| `x²` | `^2` | |
| `x³` | `^3` | SHIFT側 |
| `√` | `sqrt(` | |
| `³√` | `cbrt(` | SHIFT側 |
| `x√` | `xroot(` | SHIFT側、§3-5 |
| `x^y` | `^(` | |
| `10^x` | `pow10(` | SHIFT側 |
| `log` | `log(` | |
| `ln` | `ln(` | |
| `sin` `cos` `tan` | `sin(` `cos(` `tan(` | |
| `sin-1` `cos-1` `tan-1` | `asin(` `acos(` `atan(` | SHIFT側 |
| `π` | `pi` | |
| `x!` | `fact(` | SHIFT側、§3-6 で新設 |
| `nPr` `nCr` | `nPr` `nCr` | 中置に変更、§3-5 |
| `°'"` | `dms` | 新設、§3-4 |
| `Ans` | `ans` | 新設、§3-6 |
| `Shift` | **データから削除** | §3-7 |
| `RADモード` | **データから削除** | §3-8 |

数字トークン（`3.46` など）は従来どおり1文字ずつに分解する。

### 3-4. `°'"`（度分秒）キーを新設する

3級の三角関数は `tan 85°29'17"` の形で出る。25問がこれを使っており、
いまはキー自体が無いので1問も打てない。

- キーを押すと、式に `°` → `'` → `"` の順で区切り記号を入れる
  （直前に入れた区切りを見て次を決める）。
- 評価の直前に前処理で通常の数式に展開する。

```
85°29'17"   →   (85+29/60+17/3600)
84°10'      →   (84+10/60+0/3600)
```

> **実測**: この展開で問題 032 / 043 / 053 を計算すると、それぞれ
> `-474.58` / `-889.25` / `-21.35` となり、記載の答えと一致した。

既存の DMS パネル（`toggle-dms` とダイアログ）は、この キーで同じことが
その場でできるので **廃止する**。キーパッドの枠を1つ空けるためでもある（§3-9）。

### 3-5. `ʸ√x` と `nPr` `nCr` を「中置」に直す

いまはこの3つを関数の挿入として扱っているため、`5 nPr 3` と打つと
`5*nPr(` になってしまい、実際の電卓の打ち方が再現できない。
どれも **数値のあとに押して、次の数値を取る二項演算** として実装する。

| 打つ順 | 作られる式 | 意味 |
|---|---|---|
| `4` `ʸ√x` `3.56` | `xroot(4,3.56)` | 3.56 の 4乗根 |
| `5` `nPr` `3` | `nPr(5,3)` | |
| `8` `nCr` `5` | `nCr(8,5)` | |

閉じかっこは §3-1 の自動補完に任せる。
scope に `xroot(n, a) = a^(1/n)` を追加する（既存の `yroot(x,y)` は引数の順が
打つ順と逆で紛らわしいので、`xroot` に寄せて `yroot` は残さない）。

> **実測**: `xroot` 形式で問題 033 / 052 を計算すると `48.41` / `65.68` となり、
> 記載の答えと一致した。

### 3-6. 新設するキー: `x!` と `Ans`

- `x!` — 直前の数値・かっこの後ろに付く後置演算。式には `fact(` を中置と同じ要領で
  差し込み、scope の `factorialSafe` を `fact` として公開する。実務計算4問が使う。
- `Ans` — 直前の `=` の結果を差し込む。`state.result` を数値リテラルとして
  挿入するだけでよい。**ただしこれを使う問題は110だけで、110は2級なので外れる（§4-1）。
  ドリルには要らない。** 単体の関数電卓としてあると便利なので優先度を下げて残す。

### 3-7. SHIFT はデータに書かず、ドリルが自動で差し込む

いま問題データには `Shift` が31問に書かれているが、キーの action は
`toggle-shift` なので一致せず、そこで手が止まる。

**データからは `Shift` を消す。** 代わりにドリル側で、
次に必要な action が SHIFT 側のキー（`^3` `cbrt(` `xroot(` `pow10(` `exp(`
`asin(` `acos(` `atan(` `fact(` `nCr`）で、かつ SHIFT がまだ点いていなければ、
**その手番の「押すべきキー」を `toggle-shift` に差し替える**。

こうすると、データを書く人は SHIFT を意識しなくてよく、
キーパッドの配置を変えても問題データを直さずに済む。

### 3-8. 角度モードは「手順」ではなく「問題の属性」にする

いま `RADモード` という手順が6問に混じっているが、
`toggle-angle` は切り替えなので、すでに RAD のときに押すと DEG に戻ってしまう。

問題データに `angleMode: "DEG" | "RAD"`（既定 `"DEG"`）を持たせ、
**現在のモードが問題の要求と違うときだけ、DEG/RAD キーを押すべきキーにする**。
合っていれば手順に出てこない。手順の途中でモードを変えることはない。

### 3-9. キーパッドの配置

キーの数は増やさない（増やすとキーが小さくなり、目線移動を減らす目的と衝突する）。
DMS パネルを廃止して空いた1枠と、SHIFT 側への集約で吸収する。

```
行1  SHIFT   DEG/RAD  °'"     STAT    AC          ← DMS を °'" に置換
行2  MC      MR       M+      M-      DEL
行3  sin     cos      tan     π       e            (SHIFT: sin⁻¹ cos⁻¹ tan⁻¹)
行4  x²      √        xʸ      log     ln           (SHIFT: x³  ³√  ʸ√x  10^x  eˣ)
行5  nPr     x!       ×10ⁿ    (       )            (SHIFT: nCr  Ans)
行6  7 8 9 ÷ ×
行7  4 5 6 - +
行8  1 2 3 [=  幅2]
行9  [0 幅2]  [± 幅2]  .
```

## 4. 問題データの仕様

### 4-1. 出題は3級・4級だけにする

**いま 5問（108 / 110 / 117 / 119 / 126）は 2級の過去問なのに `level: "3級"` と
書かれている。** `exam_ref` にはっきり「第82回 2級(1) 問1」などと入っている。

- `level` は `"3級" | "4級"` のみとし、この5問は出題対象から外す。
- 2級を混ぜない理由: 級を選んで練習する道具で、選んだ級より上の問題が
  黙って混ざると、解けないのが自分のせいなのか出題のせいなのか分からなくなる。
- 検算テスト（§6）に「`exam_ref` の級表記と `level` が食い違っていないか」も入れる。

なお 110 だけは答えが `21°26'` と度分表記で、数値比較ができない唯一の問題だった。
これが外れるので、**§3-6 の `Ans` キーは必須ではなくなる**（`Ans` を使う問題は
110 だけだった）。単体の関数電卓としてはあると便利なので、優先度を下げて残す。

### 4-2. 級ごとの問題数がひどく偏っている

| | 四則計算 | 応用計算 | 関数計算 | 実務計算 | 計 |
|---|---|---|---|---|---|
| 4級 | 17 | 2 | 0 | 1 | **20** |
| 3級 | 44 | 2 | 51 | 33 | **120**（うち5件は2級） |

4級を選んだ生徒には **20問しか出ない**。しかも4級で実際に問われる
「四則計算を速く正確に」の練習にしては少なすぎる。
3級側の整備とは別に、**4級の問題を足す作業が要る**（この仕様の対象外だが、
やらないと4級の練習にならない）。

### 4-3. スキーマ

`data/exam-problems.json` のスキーマを次のように改める。

```jsonc
{
  "id": "003",
  "level": "3級",              // "3級" | "4級"
  "category": "四則計算",       // 四則計算 | 関数計算 | 応用計算 | 実務計算
  "exam_ref": "第82回 問3",
  "question": "3.75 × { 1.59 - ( 2.94 + 5.92 ) ÷ ( 7.04 - 6.58 ) }",
  "answer": "-66.27",
  "angleMode": "DEG",          // 省略時 "DEG"（§3-8）
  "rounding": { "kind": "decimals", "value": 2 },   // または
  // "rounding": { "kind": "sigfigs",  "value": 3 },
  "guide": ["3.75", "×", "(", "1.59", "-", "(", "2.94", ...]
}
```

いまの `note: "小数第2位まで"` という自由文は、機械が読めないので
`rounding` に構造化する。自動検算（§6）が「どこまで丸めて比べるか」を
これで判断する。画面には従来どおり「小数第2位まで」と日本語で出す。

`guide` に `Shift` と `RADモード` は **書かない**（§3-7 / §3-8）。

## 5. 画面の仕様

### 5-1. 何が問題だったか

いまは 上から **問題カード → 進捗バー → 電卓の画面 → キーパッド → 140行の問題一覧表**
と積み上がっている。1キー打つたびに、問題文（一番上）と光っているキー（真ん中）を
往復することになる。さらに問題一覧が常時開いているのでページが縦に長い。

### 5-2. ディスプレイ集約型

問題文・入力中の式・答え・**次に押すキー** を1枚のパネルにまとめ、
その真下にキーパッドを置く。パネルの **一番下** に「次に押すキー」を置くのが要点で、
キーパッドとの距離が最短になる。

```
┌──────────────────────────────────────────┐
│ 3級  四則計算                  問 7 / 24  │  ← メタ
│                                          │
│ 7.14 − { 9.36 − ( 2.85 + 3.19 ) × …  }   │  ← 問題文
│ 小数第2位まで                             │  ← rounding
│ ─────────────────────────────────────    │
│              7.14−(9.36−(2.85+           │  ← 入力中の式（右詰め）
│                                    0     │  ← 答え（右詰め・大きく）
│ ─────────────────────────────────────    │
│  ▶ つぎに押すキー   3           7 / 18   │  ← ここがキーパッドに一番近い
└──────────────────────────────────────────┘
                  ↓ 8px
┌──────┬──────┬──────┬──────┬──────┐
│  7   │  8   │  9   │  ÷   │  ×   │
│  4   │  5   │  6   │  −   │  ＋  │
│  1   │  2   │ ▶3   │      =      │
└──────┴──────┴──────┴──────┴──────┘
```

- 問題文が長いときは2行まで表示し、3行目以降は折りたたむ。
  全文は「問題文をひらく」で開ける（**縮めた状態でも式の構造が読めるように、
  かっこの対応を保った位置で折る**）。
- 入力中の式は右詰め・等幅。2行を超えたら先頭側を省略して末尾を見せる。
- **正解後は「次の問題」ボタンをこのパネルの中に出す。** キーパッドの下まで
  目線を落とさせない。
- 問題一覧テーブルは **既定で閉じる**。キーパッドの下に折りたたみで置く。

### 5-3. ハイライト（DADS準拠）

**いまのハイライトは見えていない。** `ring-yellow-400` を
ライトモードのキー背景（`zinc-100`）に対して測ると **1.39:1**。
DADS が非テキスト要素に求める **3:1** を大きく下回る。

| | 現在 | 変更後 | 対キー背景のコントラスト |
|---|---|---|---|
| ライト | `yellow-400` | `amber-700` | 1.39:1 → **4.57:1** |
| ダーク | `yellow-300` | `amber-400` | 10.33:1 → 8.92:1（どちらも可） |

（`amber-600` は対 `zinc-100` で 2.90:1 と 3:1 にわずかに届かないので採らない。）

**色だけに情報を乗せない**ため、ハイライトは次の3つを同時に出す。

1. 対象キーそのものを枠線で囲む（画面を暗くする方式は採らない）。
2. 対象キーの左上に `▶` を出す。
3. ディスプレイ最下段に「つぎに押すキー **3**」とテキストで書く。

枠線は対象キー1つに収め、隣のキーにはみ出さない。

### 5-4. 違うキーを押したとき

いまは何も起きない（無反応）。何が悪いのか分からないので、
**ディスプレイ最下段のヒント行を 0.8秒だけ**
「そのキーではありません。つぎは **3** です」に差し替える。
色は変えない（文言で伝える）。`prefers-reduced-motion` 時もこの文言だけは出す。

### 5-5. 文字サイズ

| 要素 | サイズ | 行間 |
|---|---|---|
| 問題文 | 20px / bold | 140% |
| 入力中の式 | 18px 等幅 | 130% |
| 答え | 32px 等幅 | 100% |
| つぎに押すキー（ラベル） | 16px | 100% |
| メタ（級・分野・問番号） | 16px | 100% |
| キーの文字 | 16px（sm以上18px） | 100% |

14px は使わない。

## 6. 自動検算（ビルド時）

問題データを足すたびに人が電卓を叩いて確かめるのは続かない。
**テストで機械が全問を打つ。**

`src/features/calc-drill/data/problems.test.ts` に置き、`npm run test:run` と
ビルド前に走らせる。1問ごとに次を確かめる。

1. `guide` の全トークンが変換表（§3-3）で action に変換できる。
2. 変換した action がすべてキーパッド上に実在する
   （＝ `CalcKeypad` の `BUTTON_ROWS` を **export して** 突き合わせる。
   いまは非公開なので、テストが実物とずれる余地がある）。
3. その action を順に `useCalculator` へ流し、`=` の時点で `hasError` にならない。
4. 出た値を `rounding` の桁で丸めた結果が、記載の `answer` と一致する。
5. `exam_ref` の級表記と `level` が食い違っていない（§4-1）。

**どれか1つでも落ちた問題は、出題対象から自動的に外す**（`DRILL_PROBLEMS` に入れない）。
テストは失敗させず、落ちた問題の一覧を出力する。理由:

- ビルドを止めると、1問のデータ誤りでサイト全体が出せなくなる。
- 一方、検算に落ちた問題を出すと **生徒に間違った答えを教える**。これは絶対に避ける。

落ちた一覧は `docs/design/calc-drill-known-bad.md` に書き出し、
過去問の原本と突き合わせてから戻す。

## 7. 進め方

| 段 | 内容 | 効果 |
|---|---|---|
| 1 | §3-1 `=` の自動補完、§3-2 `×10ⁿ` の指数表記化 | `=` エラー 19問 → 0問（実測済み） |
| 2 | §6 の自動検算テストと、落ちた問題の自動除外 | 間違った答えを教えなくなる |
| 3 | §3-3〜3-9 キーの追加と変換表 | 打てない 65問が打てるようになる |
| 4 | §5 画面の作り直し | 目線移動が減る／ハイライトが見えるようになる |
| 5 | §6 の一覧を過去問と突き合わせて修正 | 出題数が戻る |

段1・2 を先にするのは、**いま生徒が実際にぶつかっている `=` エラーを最短で消し、
間違った答えを見せない状態を先に作る**ため。画面の作り直しはその後でよい。

## 8. まだ決めていないこと

- **DMS パネルの廃止**（§3-4）は、ドリルだけでなく単体の関数電卓ページの
  機能を1つ減らす。`°'"` キーで代替できる前提だが、
  パネルのほうが使いやすい場面があるなら残す判断もある。
- **過去問の原本**が手元にないため、§6 の表の「要確認」は
  問題文が正しい前提での見立てにとどまる。原本があれば確定できる。
- **4級の問題を足すか**（§4-2）。いまのままだと4級は20問しかなく、
  「4級」を選んだ生徒はすぐ一周してしまう。過去問を足すのか、
  同じ形の問題を自動生成するのか（4級の四則計算なら生成できる）で作りが変わる。
- 苦手な手順だけを復習する機能（現在のページ内 FAQ が「繰り返し解いてください」と
  答えている部分）は、この仕様には含めていない。
